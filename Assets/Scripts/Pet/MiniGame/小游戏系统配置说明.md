# 桌宠"点点点"小游戏系统配置说明

## 系统概述

"点点点"小游戏系统允许玩家在桌宠模式下通过快速连续点击桌宠来触发各种小游戏。目前实现的第一个小游戏是**泡泡消除小游戏**。

## 功能说明

### 1. 快速点击检测（RapidClickDetector）

**功能**：检测玩家在短时间内快速连续点击桌宠，当达到触发条件时自动启动小游戏。

**触发条件**：
- 在指定时间窗口内（默认2秒）达到指定点击次数（默认10次）
- 两次点击之间的间隔不超过指定时间（默认0.5秒）

**位置**：
- 脚本会自动添加到Pet对象的Canvas子对象上
- 如果没有找到Canvas子对象，会在PetController的Awake中自动创建

**配置参数**：
- `requiredClicks`: 触发小游戏所需的点击次数（默认：10）
- `clickTimeWindow`: 检测快速点击的时间窗口，单位秒（默认：2.0）
- `maxClickInterval`: 两次点击之间的最大时间间隔，单位秒（默认：0.5）

### 2. 小游戏管理器（MiniGameManager）

**功能**：管理所有可用的小游戏，负责启动和结束小游戏。

**位置**：
- 在GameManager的Awake中自动创建
- 位于GameManager对象下（作为GameManager的子对象，方便在场景中找到）

**UI容器（MiniGameContainer）**：
- **作用**：作为小游戏UI的容器，所有小游戏的UI都会显示在这个容器内
- **位置**：自动在Pet对象下创建（与其他UI元素如BottomMenu、BarkUI_Container、PlayerInputContainer、MouseAndKeyInput同级）
- **配置**：无需手动配置，系统会在Pet创建后自动创建
- **层级结构**：
  ```
  Pet (主对象)
  ├── Canvas (交互区域，挂载PetInteraction)
  ├── BottomMenu
  ├── RightMenu
  ├── BarkUI_Container
  ├── PlayerInputContainer
  ├── MouseAndKeyInput
  └── MiniGameContainer (小游戏UI容器，自动创建)
      └── 小游戏UI会动态创建在这里
  ```

### 3. 泡泡消除小游戏（BubblePopMiniGame）

**功能**：从桌宠下方冒出彩色泡泡，玩家需要在规定时间内点击消除。

**游戏规则**：
- 游戏开始时生成初始数量的泡泡
- 持续生成新泡泡直到达到最大数量
- 玩家点击泡泡即可消除，获得分数
- 游戏有固定的时间限制
- 游戏结束后根据得分给予好感度奖励

**配置参数**：
- `gameDuration`: 游戏时长，单位秒（默认：30）
- `initialBubbleCount`: 泡泡初始数量（默认：15）
- `maxBubbleCount`: 泡泡最大数量（默认：25）
- `bubbleSpawnInterval`: 泡泡生成间隔，单位秒（默认：1.5）
- `bubbleSizeRange`: 泡泡大小范围，单位像素（默认：50-120）
- `bubbleColors`: 泡泡颜色数组（默认：6种颜色）

## Unity中配置步骤

### 步骤1：确保文件已正确创建

确认以下文件已创建在项目中：
- `Assets/Scripts/Pet/MiniGame/RapidClickDetector.cs`
- `Assets/Scripts/Pet/MiniGame/MiniGameManager.cs`
- `Assets/Scripts/Pet/MiniGame/MiniGameBase.cs`
- `Assets/Scripts/Pet/MiniGame/BubblePopMiniGame.cs`

### 步骤2：检查UI层级结构

根据你的描述，UI层级结构如下：
```
MainCanvas (场景中的主Canvas)
└── Pet (预制体，Image组件，挂载PetController)
    ├── Canvas (交互区域，挂载PetInteraction和RapidClickDetector)
    ├── BottomMenu (右键菜单 - 底部)
    ├── RightMenu (右键菜单 - 右侧)
    ├── BarkUI_Container (气泡对话UI)
    ├── PlayerInputContainer (玩家输入UI)
    ├── MouseAndKeyInput (鼠标键盘输入显示)
    └── MiniGameContainer (小游戏UI容器，自动创建)
        └── 小游戏UI会动态创建在这里
```

**注意**：MiniGameContainer会在Pet创建后自动创建，无需手动添加。

### 步骤3：在Inspector中配置PetController

1. 选择Pet对象（MainCanvas/Pet）
2. 在PetController组件中，你会看到：
   - **小游戏系统** 区域
   - `rapidClickDetector` 字段（通常会自动找到）
   
   如果没有自动找到，可以：
   - 手动在Pet/Canvas对象上添加`RapidClickDetector`组件
   - 或者确保Pet对象下有一个名为"Canvas"的子对象

### 步骤4：配置快速点击检测器

1. 选择Pet对象下的Canvas子对象
2. 如果已有`RapidClickDetector`组件，可以直接在Inspector中调整参数：
   - **Required Clicks**: 触发小游戏所需的点击次数（建议：5-15）
   - **Click Time Window**: 检测时间窗口（建议：1.5-3秒）
   - **Max Click Interval**: 最大点击间隔（建议：0.3-0.8秒）

### 步骤5：查看小游戏管理器（可选）

1. 在Hierarchy中找到GameManager对象
2. **MiniGameManager会作为GameManager的子对象自动创建**，可以在GameManager下找到它
3. 在Inspector中可以查看已注册的小游戏列表（通常会自动注册泡泡消除小游戏）

**注意**：如果找不到MiniGameManager：
- 检查GameManager对象下是否有MiniGameManager子对象
- 如果没有，运行游戏时会自动创建
- 可以在Console中看到相关日志：`[GameManager] 创建了MiniGameManager作为子对象`

### 步骤6：配置泡泡消除小游戏（可选）

1. 在Hierarchy中找到MiniGameManager
2. 找到其子对象BubblePopMiniGame
3. 在Inspector中可以调整游戏参数：
   - **Game Duration**: 游戏时长（建议：20-60秒）
   - **Initial Bubble Count**: 初始泡泡数量（建议：10-20）
   - **Max Bubble Count**: 最大泡泡数量（建议：20-30）
   - **Bubble Spawn Interval**: 生成间隔（建议：1-2秒）
   - **Bubble Size Range**: 泡泡大小范围（建议：40-150像素）
   - **Bubble Colors**: 泡泡颜色（可以添加或删除颜色）

### 步骤7：测试功能

1. 运行游戏
2. 在桌宠模式下，快速连续点击桌宠
3. 当达到触发条件时，应该会弹出泡泡消除小游戏
4. 点击泡泡进行消除
5. 时间结束后游戏会自动结束并返回桌宠模式

## 自定义小游戏

如果你想添加新的小游戏：

1. 创建一个继承自`MiniGameBase`的脚本
2. 实现以下抽象方法：
   - `OnInitialize()`: 初始化逻辑
   - `OnStartGame(PetController petController)`: 游戏开始逻辑
   - `OnEndGame()`: 游戏结束逻辑
3. 在`GameManager.RegisterMiniGames()`方法中注册新小游戏：
   ```csharp
   GameObject newMiniGameObj = new GameObject("NewMiniGame");
   newMiniGameObj.transform.SetParent(MiniGameManager.Instance.transform);
   NewMiniGame newMiniGame = newMiniGameObj.AddComponent<NewMiniGame>();
   MiniGameManager.Instance.RegisterMiniGame(newMiniGame);
   ```

## MiniGameContainer的作用和配置

### 作用
MiniGameContainer是小游戏UI的容器，用于：
1. **统一管理**：所有小游戏的UI都会显示在这个容器内
2. **层级控制**：通过CanvasGroup控制小游戏UI的显示/隐藏
3. **位置定位**：位于Pet层级下，与其他UI元素（BottomMenu、BarkUI_Container等）同级

### 配置方式
**无需手动配置**，系统会在以下时机自动创建：

1. **Pet创建时**：如果MiniGameManager在Start时已找到Pet对象，会立即在Pet下创建MiniGameContainer
2. **Pet创建后**：如果Pet还未创建，MiniGameManager会等待Pet创建后再创建容器
3. **小游戏启动时**：如果以上时机都未创建，会在启动小游戏时自动创建

**手动配置（可选）**：
如果需要在预制体中预先创建：
1. 在Pet预制体中手动添加一个名为"MiniGameContainer"的GameObject
2. 添加RectTransform组件，设置为全屏填充（anchorMin: 0,0; anchorMax: 1,1）
3. 添加CanvasGroup组件，初始alpha设为0
4. 系统会自动识别并使用这个容器

## 常见问题

### Q: 快速点击没有触发小游戏？
A: 检查以下几点：
1. 打开Console查看详细日志，现在会输出每一步的调试信息：
   - `[RapidClickDetector] 收到点击事件`
   - `[RapidClickDetector] 点击计数: X/Y, 已用时: X.XX/Y秒`
   - `[RapidClickDetector] 达到触发条件！`
2. 确保RapidClickDetector组件已添加到Pet/Canvas对象上
3. 确保点击速度足够快（在时间窗口内达到所需次数）
4. 确保没有在剧情模式中（剧情模式不会触发小游戏）
5. 确保没有其他对话或菜单正在显示
6. 检查MiniGameManager是否正确创建（在GameManager下）

### Q: Bark UI报错："speaker has no bark UI"？
A: 这个问题已修复：
1. 快速点击时会延迟0.1秒再触发Bark，给快速点击检测时间判断
2. 如果快速点击检测成功，会取消Bark触发，避免报错
3. 如果看到此错误，可能是延迟时间不够，可以调整`DelayedBarkCheck`中的延迟时间

### Q: 小游戏UI没有显示？
A: 检查以下几点：
1. 确保Pet对象已创建（因为MiniGameContainer在Pet层级下）
2. 确保MiniGameContainer已创建（检查Pet对象下是否有MiniGameContainer）
3. 查看Console日志，会输出容器创建的信息
4. 检查Console是否有错误信息

### Q: 找不到MiniGameManager？
A: 
1. MiniGameManager会在GameManager的Awake中自动创建，作为GameManager的子对象
2. 在Hierarchy中找到GameManager对象，展开其子对象，应该能看到MiniGameManager
3. 如果找不到，查看Console是否有相关日志
4. 运行游戏时会自动创建，无需手动添加

### Q: 如何调整小游戏难度？
A: 可以通过以下参数调整：
- 泡泡消除：减少游戏时长、增加泡泡数量、减小泡泡大小、缩短生成间隔

### Q: 如何在小游戏进行时禁用其他交互？
A: 系统已自动处理：
- 小游戏进行时，PetController的`ShouldForceIdle()`会返回true
- 桌宠会保持idle状态
- 点击桌宠不会触发对话（但会记录到快速点击检测）

## 技术细节

### 游戏模式判断
- **剧情模式**：`DialogueManager.IsConversationActive == true`
- **桌宠模式**：`DialogueManager.IsConversationActive == false`

### 小游戏生命周期
1. 快速点击触发 → `RapidClickDetector.RegisterClick()`
2. 达到触发条件 → `RapidClickDetector.OnRapidClickDetected()`
3. 启动小游戏 → `MiniGameManager.StartRandomMiniGame()`
4. 初始化游戏UI → `BubblePopMiniGame.OnStartGame()`
5. 游戏进行中 → `BubblePopMiniGame.OnGameUpdate()`
6. 游戏结束 → `BubblePopMiniGame.OnEndGame()`
7. 返回桌宠模式

### UI层级说明
- 小游戏UI位于MainCanvas下的MiniGameContainer中
- UI使用CanvasGroup进行淡入淡出动画
- 游戏区域占据屏幕的80%（从10%到90%）
